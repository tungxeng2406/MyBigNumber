# Coding Rules

## General principles
- Keep methods small and focused
- Prefer clarity over cleverness
- Validate all user inputs before processing
- Use descriptive names for variables and methods
- Keep business logic separated from UI code

## Java style
- Use final where appropriate
- Keep classes in their relevant package
- Avoid hard-coded logic in controllers
- Prefer explicit exception messages for invalid input

## Testing
- Add unit tests for numeric edge cases
- Cover invalid input handling
- Validate behavior before merging changes
